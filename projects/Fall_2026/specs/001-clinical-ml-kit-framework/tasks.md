# Tasks: Clinical ML Kit Framework — Milestones 1–4

**Input**: `specs/001-clinical-ml-kit-framework/` — plan.md, spec.md, research.md, data-model.md,
contracts/, quickstart.md; `.specify/memory/constitution.md`

**Tests**: Required. The constitution (VIII) and the spec (FR-061–FR-063) mandate test-first
development. Every capability's test task comes before its implementation task.

**Scope**: Milestones 1–4 only, ending with the mandatory post-M4 architecture review. No tasks
for M5–M11, specialty datasets, longitudinal/survival/wearable/genomic templates, or the dashboard.
User Stories 5 and 6 (specialty onboarding, dashboard) are out of scope for these milestones.

**Organization**: Phases follow the milestones. Story labels map tasks to spec user stories:
**US1** student completes a kit · **US2** author adds a kit by reuse · **US3** reviewer
approves/rejects a candidate · **US4** validity protections catch errors.

## Format

`- [ ] T### [P?] [US?] Description — file path(s). Deps: … Done when: …`

- **[P]**: Can run in parallel. Different files, no dependency on incomplete tasks, not blocked by
  an unresolved verification task, and not editing the same schema/contract as another open task.
- All paths are relative to `projects/Fall_2026/` unless they start with `/` (repository root).
- **Verification tasks** (V-xx IDs from plan.md § 21) produce `docs/verification/V-xx-*.md` containing:
  sources (title, organization, URL, version/date, priority tier 1–6), findings, decision,
  remaining uncertainty, and the spec/plan/contract sections affected. A task blocked on a V-xx
  task must not encode an assumption in its place.
- **Data rule for every task**: no participant-level All of Us data may be committed, exported, or
  used to derive fixtures or documentation examples. All fixtures are independently authored
  synthetic data.

## Implementation Strategy

1. **M1 (Phases 1–2)**: skeleton, schemas, provenance gating, generator, CI. Policy verification runs in parallel from day one.
2. **M2 (Phase 3)**: validity protections (US4) and reuse plumbing (US2). This proves SC-005 on golden patients.

4. **M4 (Phase 5)**: verification-first reference kits. Kits may finish as `requires_verification`; that status is reported, not hidden.
5. **Phase 6**: the mandatory review. Expansion is gated on its outcome.

**If a verification result contradicts the spec, plan, or contracts**: update those documents first, run `/speckit-analyze`, then implement the affected behavior. Never code around a contradiction.
